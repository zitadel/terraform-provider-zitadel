# zitadel_administrator (Resource)

One user's complete administrator role set on one explicit target, using stable InternalPermission v2. Import format: user_id:instance, user_id:organization:org_id, user_id:project:project_id, or user_id:project_grant:project_id:org_id. Percent-encode colons in IDs. Only one resource may manage a given user/target tuple.

## Example Usage

```terraform
resource "zitadel_administrator" "default" {
  user_id       = zitadel_machine_user.default.id
  resource_type = "organization"
  org_id        = zitadel_organization.default.id
  roles         = ["ORG_USER_MANAGER"]
}

resource "zitadel_administrator" "project_grant" {
  user_id       = zitadel_machine_user.default.id
  resource_type = "project_grant"
  project_id    = zitadel_project_v2.default.id
  org_id        = zitadel_organization.grantee.id
  roles         = ["PROJECT_GRANT_OWNER"]
}
```

## Schema

### Required

- `resource_type` (String) Explicit administrator scope: instance, organization, project or project_grant. There is no default scope.
- `roles` (Set of String) Complete administrator role set. Roles are validated by Zitadel for the selected scope; updates revoke omitted roles.
- `user_id` (String) ID of the human or machine user.

### Optional

- `org_id` (String) Organization target, or grantee organization for project_grant. Forbidden for instance/project scope.
- `project_id` (String) Project target or project owning the grant. Forbidden for instance/organization scope.

### Read-Only

- `id` (String) The ID of this resource.

## Import

```shell
terraform import zitadel_administrator.imported 'user-id:organization:organization-id'
terraform import zitadel_administrator.imported 'user-id:project:project-id'
terraform import zitadel_administrator.imported 'user-id:project_grant:project-id:grantee-org-id'
terraform import zitadel_administrator.imported 'user-id:instance'
```

Administrators have no server-generated assignment ID. The identity is the
user and full resource tuple. Percent-encode colons in custom IDs. Import
populates target fields and reads the existing role set without creating it.

Use one owner for the complete role set of each assignment. Updating roles
revokes any previously assigned roles omitted from the configuration. Before
adopting an assignment managed by another Terraform or Crossplane resource,
retain it while removing its previous owner, then import it into this resource.
The new and old owners must never reconcile the same assignment concurrently.

These resources call stable v2 RPCs and do not fall back to legacy APIs. The
caller needs read, write and delete permissions for its selected target. Read
uses a narrowly filtered list because the API has no Get method. A successful
empty list means the assignment is absent **from the caller's visible result**;
keep the provider's read permissions stable to avoid incorrect disappearance.
