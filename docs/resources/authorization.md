# zitadel_authorization (Resource)

One user's complete application role assignment, using the stable Authorization v2 API. Import an existing authorization by ID. Only one resource may manage a given user/project/organization assignment.

## Example Usage

```terraform
resource "zitadel_authorization" "default" {
  user_id    = zitadel_human_user.default.id
  project_id = zitadel_project_v2.default.id
  org_id     = zitadel_organization.default.id
  role_keys  = ["reader"]
}
```

## Schema

### Required

- `org_id` (String) ID of the organization the authorization belongs to. It must own the project or already have a project grant; it need not be the user's organization.
- `project_id` (String) ID of the project.
- `user_id` (String) ID of the human or machine user.

### Optional

- `role_keys` (Set of String) Complete set of role keys. Updating this set revokes roles omitted from it.

### Read-Only

- `id` (String) The ID of this resource.
- `state` (String) Observed authorization state. This resource does not activate or deactivate authorizations.

## Import

```shell
terraform import zitadel_authorization.imported 'existing-authorization-id'
```

Import uses only the existing authorization ID. Read populates the user,
project, organization and roles through Authorization v2. The organization is
where the authorization is granted; it need not be the user's home organization.

Use one owner for the complete role set of each assignment. Updating roles
revokes any previously assigned roles omitted from the configuration. Before
adopting an assignment managed by another Terraform or Crossplane resource,
retain it while removing its previous owner, then import it into this resource.
The new and old owners must never reconcile the same assignment concurrently.

These resources call stable v2 RPCs and do not fall back to legacy APIs. The
caller needs read, write and delete permissions for its selected target. Read
uses a narrowly filtered list because the API has no Get method. A successful
empty list means the assignment is absent **from the caller's visible result**;
keep the provider's read permissions stable to avoid incorrect disappearance.
